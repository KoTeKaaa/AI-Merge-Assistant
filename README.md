# AI-Merge-Assistant

> ИИ-ассистент QA-инженера: генерирует тест-кейсы и автотесты по изменениям в ветке, проверяет покрытие нового кода и разрешает мерж, когда условия выполнены.

**Статус:** 🚧 в разработке (кейс-чемпионат B2B-РТС, задача 9 «ИИ-Ассистент QA-инженера»). README временный и будет обновляться.

## Что это

Пользователь входит через GitHub (OAuth), выбирает репозиторий, исходную и целевую ветку. Сервис:

1. получает diff между ветками, сообщения коммитов и описание PR;
2. генерирует сценарии в формате Gherkin (Given/When/Then);
3. конвертирует сценарии в автотесты (Python + pytest);
4. проверяет, что сгенерированное валидно (шлюз качества);
5. запускает тесты в изолированном окружении и считает покрытие **нового** кода;
6. при недостаточном покрытии дописывает тесты по непокрытым строкам (несколько итераций);
7. если тесты проходят и покрытие выше порога, разрешает мерж (вручную или автоматически, по настройке).

Дополнительно поддерживается ручной режим: загрузка требований (.docx, .pdf, .md) и исходного кода (.py, .js, .java) без GitHub.

## Технологии

- **Backend:** Python, FastAPI, SQLAlchemy
- **Frontend:** см. `frontend/` (стек уточняется)
- **Тесты и покрытие:** pytest, coverage.py, diff-cover
- **LLM:** внешний API с OpenAI-совместимым интерфейсом (провайдер задаётся через `.env`)
- **Инфраструктура:** Docker, docker-compose, GitHub Actions

## Настройка (.env)

Реальный `.env` не коммитится. Шаблон лежит в `.env.example`. Основные переменные:

| Переменная | Назначение |
|---|---|
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | данные GitHub OAuth App |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | провайдер и модель LLM |
| `DATABASE_URL` | подключение к базе данных |
| `COVERAGE_THRESHOLD` | порог покрытия нового кода (по умолчанию 90) |
| `AUTO_MERGE` | разрешить автоматический мерж (`true`/`false`) |

(Список предварительный, уточняется по мере разработки.)
